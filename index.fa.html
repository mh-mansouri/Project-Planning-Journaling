برنامه‌ریزی و مستندسازی پروژه

یک Skill برای Claude که پیش از نوشتن حتی یک خط کد، دامنهٔ پروژه را درست تعریف می‌کند، و سپس یک مستند/ژورنال زنده و قابل‌ادامه از هر اتفاقی که در طول پروژه می‌افتد نگه می‌دارد.

مشاهده در GitHub دانلود .skill پرامپت همگانی (هر چت هوش مصنوعی)

کاری که انجام می‌دهد

دریافت اطلاعات اولیهٔ پروژه

پیش از دست‌زدن به کد: نوع پروژه، اینکه آیا مخزن Git وجود دارد (نام، سطح دسترسی، مجوز در صورت نبود)، اهداف کوتاه‌مدت در برابر بلندمدت، و مسیر عمومی در برابر محصول خصوصی.

یک پوشهٔ ژورنال اختصاصی

project-journal/، جدا از کد منبع: یک README داشبوردی، یک لاگ تصمیم‌ها، کدهای واقعی، یادداشت‌های اختیاری برای هر نشست.

یک داشبورد قابل‌مرور سریع

زبان ساده، جدول‌ها و نمودارهای Mermaid به‌جای نثر، چک‌لیست برای هر نقطهٔ عطف، بخش‌های تاشوندنی برای هر چیز طولانی.

خودش را به‌روز نگه می‌دارد

پس از هر گام، تصمیم، commit یا push مهم، نقشهٔ راه، لاگ تصمیم‌ها، تاریخچهٔ Git و گام‌های بعدی را به‌روزرسانی می‌کند.

یک روش توسعه برای انتخاب

spec-first (برنامه‌ریزی کامل پیش از شروع)، interactive/iterative (انعطاف‌پذیر، ژورنال تصمیم‌ها را پس از وقوع ثبت می‌کند)، یا ترکیب مبتنی‌بر نقطهٔ عطف.

بازبینی دوره‌ای، نه فقط رویدادمحور

با هر فاصلهٔ زمانی که انتخاب کنید (پیش‌فرض: هفتگی): لینک‌ها هنوز کار می‌کنند، هیچ تصمیمی بی‌سروصدا نقض نشده، هیچ موردی در نقشهٔ راه بدون توجه رها نشده، منابع ذکرشده هنوز معتبرند.

استفاده از آن

برای هر چیزی که تا الان ساختیم یک ژورنال پروژه بساز و از این به بعد به‌روزش نگه دار.

ژورنال پروژه را باز کن و بگو کجا متوقف شده بودیم.

مبتنی بر پژوهش و رویه‌های تثبیت‌شده

این گام‌ها از هیچ ساخته نشده‌اند — بر پایهٔ ده منبع آزادانه در دسترس (رکوردهای تصمیم معماری، چارچوب‌های مستندسازی، قراردادهای changelog و commit، روش‌شناسی فاز کشف، Scrum) به‌علاوهٔ پنج کتاب/استاندارد منتشرشدهٔ تجاری که فقط مفهومشان ذکر شده است. فهرست کامل، همراه با شواهد معتبر بودن مستقل هر منبع (نه صرفاً اولین نتیجهٔ جست‌وجو)، در research.md. این مخزن گام ششمِ خودش را هم اجرا می‌کند: دو Action هفتگی در GitHub — check-links و reference-review — این فهرست را صادق نگه می‌دارند.
